# RisenDev Growth Assistant — Database & Laravel Migration Blueprint

**DB:** MySQL 8+ (verify exact deployment version) · **Framework:** Laravel 13 · **Storage:** UTC datetime/timestamps.  
This document defines the **domain migration specification and copy-ready baseline migration**. Use separate migration files per table or a coherent initial migration for a fresh MVP; once deployed, always use additive changes. Keep Laravel framework auth/queue tables as generated by your installed version.

## 1. Data model rules
- Primary keys: `id BIGINT UNSIGNED AUTO_INCREMENT`; FKs match type.
- Provider IDs are `VARCHAR(191)` strings, not numeric.
- Long post/comment text uses `LONGTEXT`/`TEXT`; tokens use encrypted `TEXT`, never `VARCHAR(255)`.
- Enums are implemented as validated strings + PHP enums; easier to extend than SQL enum modifications.
- Use `ON DELETE RESTRICT` for audit-critical records or `SET NULL` where retention requires anonymization; explicit deletion workflow, not cascading destructive chains.
- Enforce uniqueness in DB **and** in application request/business logic.
- Avoid storing full provider payload by default; redact and minimize stored fields.
- `json` metadata only for bounded supplementary provider context, not critical relational fields.
- Never expose encrypted token model attributes in API/logs.

## 4. Application-layer invariants (critical)
Database constraints alone do not guarantee workflow correctness. Implement these within transactions/row locks and test:
1. **Score 0–100**; validate incoming AI output as integer in range, never cast invalid text to 0.
2. **Approval validity:** approval.decision=`approved`, approved snapshot hash equals current draft revision, approved target/platform equals lead's post, and no later edit/rejection supersedes it.
3. **No duplicate posting:** unique dispatch key generated from explicit operation; lock candidate and check existing verified or `verification_required` attempts before new publish. Do not automatically retry uncertain publish results.
4. **No publish using revoked token:** check account state + required scopes immediately before sending.
5. **Manual posted is not API verified:** record independent method/status, and require explicit confirmation.
6. **AI source isolation:** treat post text as untrusted; strip injection-like instructions from prompts by robust role/context segregation rather than relying only on regex.
7. **Encrypted casts:** map `access_token_encrypted` and `refresh_token_encrypted` to Laravel `encrypted` cast; avoid double encryption. Column naming indicates storage purpose, not requirement to manually pre-encrypt.
8. **Soft delete keyword:** unique index still covers deleted values; restore/reactivate previous record when user re-adds same normalized phrase.
9. **No cross-account mismatch:** `discovery_run.social_account.platform`, keyword platform, and post platform must align; validate at action level.

## 7. Test plan for schema
```bash
php artisan migrate:fresh
php artisan migrate:status
php artisan test
```
- Create duplicate `(platform, external_post_id)` → must throw unique constraint.
- Create same post in two runs → one post, two pivot records.
- Reject missing FK, invalid scope/status at service validator.
- Create approved draft revision then edit → service should reject old approval for send.
- Duplicate `dispatch_key` → unique constraint.
- Disconnect account → tokens cleared, historical engagements retained.
- Migration rollback on **development DB only**; production rollback must be planned separately.

## 8. Production evolution considerations
- Prefer separate migration files per table once collaborative development starts.
- Add `tenant_id` only when SaaS is intentionally approved; do not retrofit by guessing.
- Archive or prune raw discovered post content according to data-use terms and configured retention.
- On large tables, use online/index-safe migration strategy and query plans rather than adding indexes arbitrarily.
- Prefer bigint PK for internal data, provider ID strings for external data.
